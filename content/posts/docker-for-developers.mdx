Docker can feel like infrastructure voodoo when you're coming from a pure frontend or full-stack background. Here's the practical subset that gets you from zero to shipping.

## Multi-stage Builds

Don't ship your dev dependencies to production. Multi-stage builds let you compile in one image and copy only the artifacts to a slim final image:

```dockerfile
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:22-alpine AS runner
WORKDIR /app
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/package.json ./package.json
EXPOSE 3000
CMD ["npm", "start"]
```

This pattern alone can shrink your production image from 1.2GB to under 200MB.

## Docker Compose for Local Dev

A good `docker-compose.yml` makes onboarding trivial. New teammate? `docker compose up` and they're running.

```yaml
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - DATABASE_URL=postgres://user:pass@db:5432/mydb
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
    volumes:
      - pgdata:/var/lib/postgresql/data
```

## The Gotchas

- **Layer caching is order-sensitive.** Copy `package.json` before `COPY . .` — it prevents cache invalidation on every code change.
- **`.dockerignore` is your friend.** Exclude `node_modules`, `.git`, and build artifacts. They bloat your context and slow builds.
- **Don't run as root inside the container.** Add a non-root `USER` in your final stage. It's one line that prevents a whole class of security issues.
- **Bind mounts for dev, not for production.** Mounting your source code into a container is great for hot-reload during development, but never do it in a production Dockerfile.

## When Not to Dockerize

Not everything needs a container. Static sites deploy happily to Vercel or Netlify. Serverless functions handle bursty workloads better than always-on containers. Docker shines when you need predictable, reproducible environments — use it where it adds value, not everywhere.
